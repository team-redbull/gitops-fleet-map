# e2e: the real image on a real cluster against a GitLab-shaped server

Fake teams `a`, `b`, `c`, a made-up day1 repo (generated by `seed.py`), the Ubuntu-based image from `build-ubuntu.sh`, a real Kubernetes (k3s), the README's Deployment (SIGS_URL, DAY1_URL, token Secret mounted at GITLAB_TOKEN_FILE) run as UID 1000700000 with a read-only root.

```sh
sh e2e/up.sh      # fake GitLab + seed, k3s, image build/load, Deployment, port-forward on http://localhost:18080
sh e2e/check.sh   # static + UI checks, idle request counts, mutation test, outage test (~13 min: they wait on the 60s refresh interval)
sh e2e/down.sh
```

| file | what |
|---|---|
| `fake_gitlab.py` | the GitLab stand-in (groups/projects/commits/tree/branches/archive API, version, PATs with scopes + expiry, git smart HTTP for seeding, optional URL sub-path, `/__ctl`: request log, forced 429, hostile archives; also driven by `tests/fetch_test.py`). **Not real GitLab**: `gitlab/gitlab-ce` is on Docker Hub, which the sandbox proxy blocks. Swap in a real instance by pointing `seed.py` at it. |
| `seed.py URL ROOT_TOKEN` | creates `org/day2/sigs/{a,b,c}` and `org/day1/platform-config` through the REST API. The comments in it say which tenant shows which status/warning. Idempotent (skips repos that have content). |
| `k3s.sh` | installs/starts single-node k3s (kind needs `kindest/node` from Docker Hub). Works around a sandbox without `CAP_SYS_RESOURCE` (`restrict_oom_score_adj`). |
| `k8s.yaml` | the README Deployment + Service + the OpenShift-like securityContext, `/data` and `/tmp` as emptyDirs; `__HOSTIP__` is filled in by `up.sh`. |
| `live_check.py static\|idle\|mutate\|outage` | the assertions; screenshots go to `e2e/shots/`. |

State (tokens, repos, logs) is in `e2e/.state/`. Reseed from scratch: `sh e2e/gitlab.sh stop; rm -rf e2e/.state/gitlab; sh e2e/up.sh`.
Prerequisites: docker, debootstrap, python3 with PyYAML and Playwright (chromium), root, outbound HTTPS to github.com (k3s release) and archive.ubuntu.com (image build).
